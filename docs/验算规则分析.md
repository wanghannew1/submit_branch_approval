## 四、核心公式（通用所有劳务外包模板）

唯一行公式（替代原来的两个公式）：

```
转款合计 = 代理费 + 意外险 + 养老个人 + 失业个人 + 实发工资 + 个税
```

LHS = `transfer_total`
RHS = `proxy_fee` + `accident_insurance` + `endowment_personal` + `unemployment_personal` + `net_total` + `personal_tax`

验证方式：在 **每个数据行** 与 **合计行** 分别校验。

#### 数据验证（任选一行验证）

| 样本 | 行 | 代理费 | 意外险 | 养老个人 | 失业个人 | 实发工资 | 个税 | 转款合计 | 结果 |
|------|:--:|:------:|:------:|:--------:|:--------:|:--------:|:---:|:--------:|:----:|
| 天池酒店 | 5 (刘刚) | 256.5 | 0 | 0 | 0 | 2700 | 0 | 2956.5 | ✅ |
| 天池酒店 | 6 (崔金龙) | 952.45 | 0 | 351.46 | 13.18 | 2707.77 | 0 | 4024.86 | ✅ |
| 天池酒店 | 12 (姜良富) | 266 | 144.8 | 0 | 0 | 2800 | 0 | 3210.8 | ✅ |
| 天池酒店 | 28 (单体生) | 1763.79 | 0 | 351.46 | 13.18 | 5285.27 | 39.75 | 7453.45 | ✅ |
| 天池酒店 | 合计行 | 36297.92 | 144.8 | 10543.8 | 395.4 | 148216.97 | 59.74 | 194929.35 | ✅ |
| 雪绒花 | 5 (杨卉君) | 1178 | 0 | 351.46 | 13.18 | 3435.36 | 0 | 4978 | ✅ |

**推导**：原公式 A（转款合计=代理费+意外险+应发工资）+ 公式 B（应发工资=养老个人+失业个人+实发工资+个税）→ 代入消去 `应发工资` 得此单一公式。

### 子项目验证（辅助理解，不单独配行公式）

#### 验证 1：应发工资构成

```
应发工资 = 养老个人 + 失业个人 + 实发工资 + 个税
```

此关系已 **隐含在主公式** 中（主公式右边已包含 `养老个人+失业个人+实发工资+个税`），无需单独配置行公式。做数据一致性理解的辅助参考。

#### 验证 2：代理费构成（弱检查）

```
代理费 >= 单位养老 + 单位失业 + 工伤
```

代理费包含单位保险部分 + 多余服务费。无独立「多余服务费」列，故无法做等式校验。可配置为弱检查：`proxy_fee >= endowment_company + unemployment_company + industrial_injury`

## 五、正确验算规则设计

### 5.1 通用规则（所有模板共有）

#### 纵向加总检查（column_sum_checks）

适用于所有模板的数值列：

```json
["应发工资", "代理费", "转款合计", "实发工资"]
```

每列的数据行加总应与合计行的对应值一致（误差 0.01 以内）。

> **注意**：天池/景区模板中，合计行第 5 列为「意外险」加总而非「五险一金单位缴纳」加总。索引映射需按实际列位置为准。

#### 额外汇总行检查（extra_summary_checks）

所有模板相同：

```json
{
  "name": "转款合计 = 溢缴款抵扣 + 甲方转款",
  "column": "transfer_total",
  "lhs_row_key": "summary",
  "rhs_plus_row_keys": ["overpayment_offset", "party_a_transfer"],
  "rhs_minus_row_keys": []
}
```

### 5.2 核心行公式（所有劳务外包模板通用）

单一公式（代入消去 `应发工资` 后合并得来）：

```
转款合计 = 代理费 + 意外险 + 养老个人 + 失业个人 + 实发工资 + 个税
```

LHS = `transfer_total`
RHS = `proxy_fee` + `accident_insurance` + `endowment_personal` + `unemployment_personal` + `net_total` + `personal_tax`

```json
{
  "name": "转款合计 = 代理费 + 意外险 + 养老个人 + 失业个人 + 实发工资 + 个税",
  "lhs": "transfer_total",
  "rhs_plus": ["proxy_fee", "accident_insurance", "endowment_personal", "unemployment_personal", "net_total", "personal_tax"],
  "rhs_minus": []
}
```

### 5.3 列加总检查（所有劳务外包模板通用）

```json
["gross_pay", "proxy_fee", "transfer_total", "net_total"]
```

> 雪绒花模板因有 `扣款合计` 列，额外加 `deduction_total`：
> ```json
> ["gross_pay", "proxy_fee", "transfer_total", "deduction_total", "net_total"]
> ```
> `扣款合计` 列仅做纵向加总，不做行公式校验。

## 九、总结

1. **根本问题**：现有默认验证规则假设模板包含完整的 13 个 Payroll 字段，但天池酒店/景区/雪绒花模板只包含其中一部分，导致公式引用不存在的列而失败。

2. **解决方案**：为不同类型的模板定义独立的规则集，通过 `detect_rule_set()` 自动匹配或用户手动选择。

3. **两套规则集**：
   - `default` — 完整 Payroll 模板（现有规则）
   - `outstaff` — 劳务外包模板（天池酒店/景区/雪绒花共用）
     - 单一公式：**转款合计 = 代理费 + 意外险 + 养老个人 + 失业个人 + 实发工资 + 个税**
     - 列加总：天池/景区用 4 列，雪绒花多 `deduction_total` 列

4. **关键差异**：`row_formulas` 是核心差异。`extra_summary_checks`（转款合计=溢缴款抵扣+甲方转款）所有模板共用。

5. **额外列键映射需要**：新规则集引用了 `company_insurance`、`endowment_personal`、`unemployment_personal` 等列键，这些需要在 `config.json` → `excel.columns` 中补充定义，或者在 `demo_app.py` 的列名解析逻辑中增强识别能力。
